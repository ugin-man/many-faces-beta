## 最初の状態

基準の実行は GitHub Actions 33913847375。ビルドは成功したが、型検査は失敗し、JavaScriptのテストは99件中98件が成功、1件が失敗した。依存関係の監査では23個の依存パッケージが報告された。これは23件の本番攻撃経路を確認したという意味ではない。

コードだけでなく、カタログ、保存先の選び方、公開API、録画と動画解析、再生、検証方法、CIを確認した。全ファイルを一行ずつ目視した監査ではない。

## 修正した問題

カタログへの書き込みは、鍵がない場合に許可されていた。設定がない場合は拒否し、利用者が送ったメールアドレスのヘッダーだけでは許可しないようにした。アップロードは読み込み中に8MBの上限を確認する。読み込み終わってからサイズを確認していた旧実装では、上限を超えたデータを先にメモリーへ取り込めてしまった。

カタログのメタデータと実際の画像が違う保存先から読まれる経路を修正した。選んだ保存先にデータがないときはエラーにし、別世代の画像で埋めない。選択結果のキャッシュも保存先ごとに分離した。画像の範囲指定は、開始位置、整数の上限、実際に返ったバイト数まで確認する。中身を変更できるURLに一年間のimmutableキャッシュを付ける処理もやめた。

動画処理には実行ごとのキャンセル信号を導入した。ファイルの読み込み、画像の準備、リセット、画面の破棄が重なっても、古い処理が後からレビューを復活させないようにした。カメラの許可がキャンセル後に返った場合も、取得したトラックを停止する。録画機能は独立したモジュールに分けた。

動画フレームの通知はシークの前に登録し、通知された映像時刻を確認する。時間切れを成功として扱わない。通信の制限時間はヘッダーが返るまでではなく、本文の読み込みまでを含む。5秒を超える元動画は、レビュー対象の末尾で再生を停止する。同じファイルの選び直し、解析密度と初期再生密度のずれ、シーク中の表示順も修正した。

表示の成功判定は、不正な数値、画像の失敗、出力が変わらない状態を拒否する。一方で、正常に処理が終わることと表情がよく似ていることは別なので、一致度の既存基準を満たしたフレーム数を別に表示する。顔の照合式、候補数、重み、合格しやすくするための閾値変更は行っていない。

出力に作者、出典、利用条件を表示する。Openverseから利用条件が欠けた項目を受け取っても、CC0と書き換えない。外部画像は許可したホストだけを読み、転送先も毎回確認する。読み込みサイズとリクエスト全体の時間にも上限を設けた。許可リスト外の画像を利用できなくなる点は、意図した制限である。

型検査を独立したコマンドとCIに追加した。テスト前にソースを書き換える方式ではなく、コミットされたソースをビルドして確かめる。古いカタログの固定値に依存したテストは、全シャードの整合性を確認するものに置き換えた。壊れた古いpatchワークフローは履歴用のフォルダーへ移した。今回の一回限りの移行スクリプトも、適用後に削除した。

## 検証と残る課題

詳しい実行結果はProject auditの各Actions実行に保存する。レポートには対象コミット、ブラウザのバージョン、動画のハッシュを含める。現在のブラウザ検証は、リポジトリに元からある動画を使う。以前の個人アップロード動画を再検証したとは扱わない。

ブラウザ検証はCloudflareのローカルWorkerdで、実際のビルド成果物を配信して行う。Vinextの別のプレビューで成功するだけでは、Worker経路やWASMのMIME型まで確かめたことにならない。

物理カメラ、iPhone/Safari、低メモリー端末、独立した評価動画での表情と角度の一致は別途確認が必要。既存のFIFO、FAST、legacyは残しているが、修正済みの/liveと同じ品質を保証していない。大きなコンポーネントや重複実装もまだ残る。

カタログは最終的には内容のハッシュを含む世代別URLにするべきで、今回の修正だけでは公開中の世代変更を完全に原子的にできない。古いブラウザ内カタログ作成UIは新しい認証鍵を送信しないため、そのままでは公開保存できない。管理者用の認証経路を使う必要がある。

依存パッケージは互換性を確かめて更新するが、未修正の上流問題を隠すための強制更新や、監査コマンドが提案した破壊的な古い版への切り戻しはしない。最終的な残件は、実行ごとのdependencies.jsonを正とする。
